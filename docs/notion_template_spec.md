## 2. 선택형 속성의 옵션값

> **v1.2부터 이 목록은 "초기값"입니다.** 봇은 실행할 때 노션에서 현재 옵션을
> 읽어 버튼을 만듭니다(§9). 아래 값은 최초 1회 심어지는 기본값이며,
> 이후 노션에서 자유롭게 바꾸시면 됩니다.

### `과목`
표를 처음 만들 때는 비워두어도 됩니다. `chapters.yaml`에 등록된 과목이
처음 저장되는 순간 노션이 옵션을 자동 생성합니다.

현재 등록 기준: `회계` `세법` `재무` `경영`
(미등록: `원가` `경제` `상법` — yaml에 추가하면 자동 반영)

### `단원`
전량 자동 생성됩니다. **수동 입력하지 마십시오.**
현재 등록 기준 102개 (회계 25 / 세법 55 / 재무 14 / 경영 8)

### `개념태그`
사용 중 누적됩니다. 초기값 없음.

### `지식유형` — 6개 (v1.2 재구성)
| 옵션 | 용도 |
|---|---|
| `기준서` | K-IFRS, 회계감사기준 등 성문 회계기준 |
| `법령` | 세법·상법 조문 |
| `이론·개념` | 학술적 이론과 개념 (재무관리 CAPM, 경영학 이론 등) |
| `산식` | 계산 구조, 공식 |
| `암기` | 요건·한도·기한 등 단순 암기사항 |
| `견해` | 내가 정리한 해석·논거 |

- `이론·개념`(v1.2): 기존 5개가 회계·세법에 치우쳐 재무·경영 지식을
  담을 칸이 없던 문제를 해결한다.
- `기준서`와 겹칠 때의 기준: **성문 규범을 인용하면 `기준서`,
  규범 없이 개념 자체를 설명하면 `이론·개념`.**

### `오답유형` — 7개 (건너뛰기 가능)
`개념 미숙지` / `개념 혼동` / `조건 오독` / `계산 실수` / `함정 미인지` / `시간부족` / `근거오류`

- `근거오류`(v1.1): 결론은 맞았으나 근거·적용 조문·논리 경로가 틀린 경우.
  변형 문제에서 무너지는 유형이라 별도로 추적한다.
- 오답이 아닌 기록(단순 질문 정리 등)은 이 단계를 건너뛴다.
  건너뛰면 노션에서 값이 비고 ④ 뷰에 그룹이 생기지 않는다.

### `교재구분` — 5개 (건너뛰기 가능)
`기출` / `객관식` / `연습서` / `모의고사` / `AI질의`

- `AI질의`(v1.1): AI와의 질의응답을 외부에서 검증·정제해 옮겨 적은 기록.
- 문제를 풀다 파생된 질의는 `교재구분`을 `AI질의`로 두되,
  `문제위치`에 원 문제를 적어 ③ 문제별 뷰에서 묶이게 한다.
- `AI질의`만 교재가 아니지만, 실무상 같은 축에 두는 편이 분류가 단순하다.

## 3. 뷰(View) 구성 — 5개

### ① 단원별 (기본 뷰) ★ 핵심
- **형식: 보드(Board)** — 테이블 뷰는 하위 그룹화를 지원하지 않음을 실측 확인함
- 필터: `과목` = 해당 과목 (과목마다 보드 뷰를 따로 만드는 것을 권장)
- **하위 그룹화(가로 레인): `단원`**
- **그룹화(세로 열): `개념태그`**
- **정렬: 알파벳순 (⚠️ `수동` 금지 — 아래 참조)**
- 설정: `빈 그룹 숨기기` 켜기
- 카드 표시 속성: 지식유형 / 오답유형 / 문제위치 / 기록일

> 단원이 가로 레인으로, 그 안의 개념태그가 열로 나뉩니다.
> 각 열 머리글에 카드 수가 표시되므로 반복해서 틀린 개념이 바로 드러납니다.
> `빈 그룹 숨기기`를 켜지 않으면 다른 단원의 태그 열까지 전부 표시되어
> 화면이 매우 넓어집니다. 반드시 켜십시오.
>
> **⚠️ 그룹 정렬을 `수동`으로 두지 마십시오.** 실측으로 확인된 문제입니다.
> 수동 정렬에서는 노션이 그룹의 순서와 표시 여부를 사용자가 관리하는
> 것으로 간주해, 다음 두 현상이 함께 발생합니다.
> - 필터가 `과목=회계`인데도 **다른 과목의 단원 그룹이 카드 없이 나타남**
> - 새로 만들어진 단원 그룹이 **한동안 보이지 않음**
>   (눈 아이콘을 껐다 켜야 나타남)
>
> 정렬을 알파벳순으로 바꾸면 노션이 그룹 목록을 매번 계산하므로
> 두 현상이 모두 사라집니다. 이는 ②~④ 뷰의 그룹화에도 동일하게 적용합니다.

### ② 과목별 (테이블)
- 그룹화: `과목` (**그룹 정렬: 알파벳순**) / 행 정렬: 기록일 내림차순
- 단일 그룹화이므로 테이블 뷰로 충분합니다.

### ③ 문제별
- 그룹화: `문제위치` (**그룹 정렬: 알파벳순**) / 필터: `문제위치`가 비어있지 않음
- 한 문제에서 파생된 여러 개념을 묶어 봅니다.

### ④ 오답유형별
- 그룹화: `오답유형` (**그룹 정렬: 알파벳순**)
- 계산 실수가 많은지 개념 혼동이 많은지 진단합니다.

### ⑤ 최근 기록
- 그룹화 없음 / 정렬: `기록일` 내림차순
- 방금 저장한 것이 제대로 들어갔는지 확인하는 용도입니다.

## 4. 만드는 순서

1. 노션에서 새 페이지 생성 → `/데이터베이스 - 전체 페이지` 선택
2. 위 1번 표대로 속성 10개를 만듭니다.
   - `개념명`은 기본 제공되는 `이름` 속성의 이름만 바꾸면 됩니다.
   - `기록일`은 타입을 **`생성 일시`** 로 지정합니다. `날짜`가 아닙니다.
3. `지식유형` `오답유형` `교재구분`의 옵션값을 위 2번대로 미리 입력합니다.
4. 3번 뷰 5개를 만듭니다. ①번만 보드 레이아웃, 나머지는 테이블입니다.
5. 색상·아이콘·커버를 원하는 대로 꾸밉니다.
6. 우측 상단 `...` → `연결` → 만들어 둔 통합(Integration) 선택
7. 우측 상단 `...` → `템플릿으로 복제 링크 만들기` → 배포용 링크 확보

## 5. 바꾸면 안 되는 것 / 바꿔도 되는 것

두 가지는 성격이 다릅니다. 뭉뚱그리면 안전한 변경까지 겁내게 됩니다.

### 5-1. 계약 — 바꾸면 저장이 실패합니다

속성의 **이름과 타입**은 코드와 노션 사이의 약속입니다.

| 행동 | 결과 |
|---|---|
| 속성 이름 변경 (`오답유형` → `오답 유형`) | 저장 실패. 원인을 찾기 매우 어려움 |
| 속성 타입 변경 (선택 → 텍스트) | 저장 실패 |
| `기록일`을 `날짜` 타입으로 생성 | 저장은 되지만 날짜가 비어 있음 |
| 통합 연결(§4의 6번) 누락 | 봇이 표를 찾지 못함 (가장 흔한 실수) |

### 5-2. 자유 — 바꿔도 안전합니다

**선택지(옵션값)는 사용자의 분류 취향입니다.** 노션 API는 없는 옵션값을 받으면
자동으로 만들어 주므로, 옵션을 더하거나 색상을 바꿔도 저장은 깨지지 않습니다.

| 행동 | 결과 |
|---|---|
| `오답유형`에 `단위 실수` 추가 | 안전 |
| 선택지 색상·정렬 변경 | 안전 |
| `과목`·`단원` 옵션이 비어 있음 | 안전 (첫 저장 시 자동 생성) |

단, 봇 버튼에도 함께 반영하려면 `bot.py`의 목록을 같이 고쳐야 합니다.

### 5-3. 주의가 필요한 것

| 행동 | 결과 |
|---|---|
| `단원`·`개념태그` 옵션을 손으로 삭제 | 그 값을 쓰던 기존 기록의 분류가 사라짐 |
| 이미 쓰이고 있는 옵션의 **이름 변경** | 노션은 기존 기록도 함께 바꿔주지만, 봇 버튼과 어긋남 |

## 6. 배포 시 사용자 절차

1. 템플릿 복제 링크 접속 → 우측 상단 `복제`
2. 노션 통합 생성 후 복제한 표에 `연결`
3. `.env`에 텔레그램 토큰 · 노션 토큰 입력 (**DB ID 불필요**)
4. 봇 실행 후 `/setup` → 버튼으로 표 선택
5. `chapters.yaml`을 본인 교재 목차로 교체

## 7. 기술 메모 (Claude Code 전달용)

### API 버전 고정
노션 API는 요청 헤더 `Notion-Version`으로 동작이 결정되며, 헤더를 올리지 않는 한
기존 동작이 유지됩니다. 따라서 **버전 문자열을 코드 상수 한 곳에 고정**하고,
그 값을 모든 요청에 사용합니다. 버전을 명시하지 않으면 동작이 달라질 수 있습니다.

2025-09-03 버전부터 `database`와 `data source` 개념이 분리되어
페이지 생성 시 `parent`에 넣는 키(`database_id` vs `data_source_id`)와
조회 엔드포인트가 달라집니다. **구현 전 공식 문서에서 현재 권장 버전과
`parent` 형식을 확인한 뒤 진행할 것.** 확인 없이 추측해서 작성하지 말 것.

### 요청 속도
노션 API는 초당 약 3회 제한이 있습니다. 태그 목록 조회처럼 반복 호출이
발생하는 지점에는 짧은 간격을 두고, 429 응답 시 대기 후 재시도합니다.

### 대상 DB 지정 (2단 방식)
1. `.env`의 `NOTION_DB_ID`가 채워져 있으면 그 값을 사용한다.
2. 비어 있으면 `/setup` 명령으로 검색 API를 호출해 접근 가능한 DB 목록을
   버튼으로 제시하고, 선택한 ID를 로컬 파일에 저장한다.
3. 검색이 실패하면 "노션 표 주소에서 ID를 복사해 `.env`에 넣어주세요"라는
   안내 메시지를 한국어로 출력한다. (조용히 실패하지 말 것)

### 단원 버튼 페이지네이션
단원이 10개를 넘으면 한 화면에 10개씩 표시하고
`[◀ 이전] [1/3] [다음 ▶]` 버튼으로 넘긴다. 과목·대분류·지식유형 등
항목이 적은 화면에는 적용하지 않는다.

## 8. 저장 정책 (v1.1 확정)

봇은 `지식유형`·`오답유형`·`교재구분` 값을 **허용 목록과 대조하지 않고
그대로 노션에 전달**한다. 옵션이 없으면 노션이 자동 생성한다.

근거: 이 값들은 봇이 스스로 만든 버튼에서만 나오므로, 저장 직전의 대조는
자기 출력을 자기 목록과 비교하는 것이어서 실패할 수 없다. 반대로 검증을
두면 옵션을 하나 추가할 때마다 저장이 실패하고, 사용자가 방금 입력한
정리 내용이 통째로 유실된다.

예외로 다음은 이 정책과 무관하게 유지한다.

- `check_notion.py`의 옵션 검사 — **v1.2에서 성격이 바뀐다.**
  노션이 옵션의 원천이 되었으므로 "명세서 목록과 같은가"는 더 이상
  오류 판정 기준이 아니다. 대신 다음만 검사한다.
    - 선택형 속성에 옵션이 **하나도 없으면 오류** (버튼이 비어 봇을 쓸 수 없음)
    - 명세서 초기값과 다른 부분은 **참고 표시만** (오류 아님)
  속성 이름·타입 검사(계약)는 오류 판정을 그대로 유지한다.
- 건너뛴 항목 처리 — 해당 속성 자체를 요청에 넣지 않는다. (빈 문자열 금지)
- `개념태그` — 유일하게 사용자가 직접 타이핑하는 선택형 값이다.
  오타로 인한 분열은 저장 시 대조가 아니라 기존 태그 버튼·검색으로 막는다.

## 9. 옵션 목록의 원천 (v1.2 확정)

`지식유형` · `오답유형` · `교재구분`의 선택지는 **노션이 원천**이다.
코드에 목록을 하드코딩하지 않는다.

### 동작 방식 — `chapters.yaml`과 동일한 패턴

```
봇 시작 → 노션에서 세 속성의 옵션 목록을 1회 조회 → 메모리에 보관
       → 그 뒤로는 조회하지 않음
옵션을 바꿨다면 → 봇을 껐다 켠다 (Ctrl+C 후 재실행)
```

매 요청마다 조회하지 않으므로 버튼이 느려지지 않는다.

### 규칙

| 항목 | 처리 |
|---|---|
| 조회 실패(네트워크·권한) | 시작 시 한국어로 안내하고 종료. `chapters.yaml` 오류와 같은 패턴 |
| 옵션이 0개인 속성 발견 | 시작 시 안내하고 종료 (버튼을 만들 수 없음) |
| 사용자가 옵션을 삭제 | 재시작하면 버튼에서 사라짐. 그 값을 쓰던 기존 기록은 노션에 그대로 남음. 별도 경고 없음 |
| 옵션이 10개를 넘음 | 단원 화면의 페이지 넘김 로직을 재사용 |
| 옵션명 길이 | 텔레그램 버튼 가독성상 12자 이내 권장 (강제하지 않음) |

### 초기값은 누가 심는가

`setup_notion.py`가 표를 만들 때 §2의 목록을 최초 1회 심는다.
그 이후로 이 스크립트는 다시 실행하지 않으며, 진실의 원천은 노션이 된다.
따라서 §2의 목록은 **시드 값**이지 런타임 기준이 아니다.

### 이 결정의 이유

옵션 변경이 개발 2주 안에 두 번 발생했고, 그때마다 `bot.py`·`setup_notion.py`·
`check_notion.py` 세 파일을 정확히 고쳐야 했다. 배포받은 사용자에게
"파이썬 파일 세 개를 고치세요"는 현실적으로 불가능한 요구이며,
따옴표 하나가 빠지면 봇이 기동하지 않고 영어 오류만 출력된다.
노션 화면에서 옵션을 바꾸는 것은 §5-2가 이미 "안전한 변경"으로 규정한 행위다.

### 배포 시 함께 처리할 문서 작업

AI 질의 정제 프롬프트(봇 외부)는 옵션 목록을 전제로 추천값을 출력한다.
사용자가 옵션을 바꾸면 그 프롬프트도 바뀌어야 하므로,
배포 문서에 "본인 노션의 옵션 목록을 프롬프트에 붙여넣어 쓰십시오"를 안내한다.

## 10. 다중 선택 전환과 표기 규약 (v1.3)

### 10-1. 왜 바꾸는가

`개념태그`를 하나만 고르게 한 설계가 실사용과 맞지 않았다.
부가세 가산세처럼 한 번의 정리가 여러 개념에 걸치는 경우가 정상이며,
사용자가 쉼표로 여러 태그를 입력했을 때 노션이 다음 오류를 냈다.

    Invalid select option, commas not allowed

노션의 선택지 이름에는 쉼표를 쓸 수 없다. 이 제약은 다중 선택에서도
동일하므로, **개별 태그 이름에 쉼표가 들어가서는 안 된다.**
쉼표는 태그를 나누는 구분자로만 쓴다.

`오답유형` 역시 계산 실수와 조건 오독이 동시에 일어나는 경우가 흔해
다중 선택으로 전환한다.

### 10-2. 계층 구조에 생기는 변화

태그를 3개 단 기록은 보드 뷰에서 **3개 그룹에 각각 나타난다.**
개념 하나를 파고들 때는 오히려 유리하지만, 그룹 개수의 합은
실제 기록 수보다 크다. 이는 결함이 아니라 다중 선택의 성질이다.

보드 뷰의 하위 그룹이 다중 선택 속성을 지원하지 않는 경우,
하위 그룹만 `지식유형`으로 바꾸고 태그는 필터로 좁힌다.

### 10-3. `개념명` 조합 규칙 (v1.5 재정의)

- **대표 개념태그**를 제목에 쓴다. 대표는 사용자가 명시적으로 지정한다(§12-2).
- 문제위치가 있으면 : `대표태그 · 문제위치`   예) `공통매입세액재계산 · 연p.부-181#03`
- 문제위치가 없으면 : `대표태그 · MM/DD`      예) `공통매입세액재계산 · 09/07`
- 제목에는 **대표 태그 하나만** 쓴다. 둘 이상을 이으면 제목이 길어져
  노션 표에서 잘린다.

**v1.4까지의 "첫 번째로 선택한 태그" 규칙은 폐기한다.** 태그 목록이
사용 빈도순으로 정렬되어 있어, 위에서부터 고르는 자연스러운 동작이
"가장 흔한 태그가 늘 제목이 됨"으로 이어졌다. 실제로 같은 문제에서 만든
세 기록의 제목이 모두 `공통매입세액 · 연p.부-181#03`으로 동일해져
노션 표에서 구분할 수 없는 상태가 관측되었다.

### 10-4. 누적 알림 규칙

선택한 태그 중 **누적 2회 이상인 것만** 최대 3개까지 알린다.
2회 이상인 태그가 없으면 알림 없이 "저장 완료"만 표시한다.
태그 5개의 횟수를 모두 나열하면 소음이 되어 경고 기능이 죽는다.

    ✅ 저장 완료
    ⚠️ #가산세중복적용배제 4번째 · #세금계산서불성실 2번째

### 10-5. `문제위치` 표기 규약

③ 문제별 뷰는 문자열이 정확히 일치해야 묶인다. 접두어를 통일한다.

| 접두 | 의미 |
|---|---|
| `연` | 연습서 |
| `객` | 객관식 |
| `기` | 기출 |
| `모` | 모의고사 |

형식: `연p.212#15`

`교재구분`을 `AI질의`로 두더라도 이 칸에 원 문제 출처를 적으면
③ 뷰에서 원 문제와 함께 묶인다. 텔레그램 입력 안내에 이 예시를 노출한다.

### 10-6. `참고출처` 표기

이 개념의 출전을 적는다. 형식을 강제하지 않는다.
예) `기준서 1116호 문단 22` · `부가가치세법 제29조 제3항` · `워p.131`

`문제위치`가 **"이 문제가 어디 있었나"**라면,
`참고출처`는 **"이 개념의 근거가 어디 있나"**이다. 텔레그램 입력 안내에서
두 칸의 차이가 드러나도록 예시를 서로 다른 성격으로 제시한다.

## 11. 운영 메모 (v1.4)

### 11-1. 「같은 문제로 하나 더」의 유지 규칙 (§10-6)

한 문제에서 여러 개념이 나오는 경우를 위한 기능이다.

| 구분 | 항목 |
|---|---|
| **유지** | 과목 · 대분류 · 단원 · **교재구분** · **문제위치** |
| **초기화** | 개념태그 · 지식유형 · 오답유형 · 참고출처 · 정리 내용 |
| 재시작 지점 | 개념태그 선택 화면 |

**교재구분과 문제위치를 다시 묻지 않는다.** 다시 물으면 같은 문제인데도
`연p.21-3#기01`과 `연p.21-3#기1`처럼 표기가 갈릴 수 있고, ③ 문제별 뷰는
문자열이 정확히 일치해야 묶이므로 기능의 목적 자체가 무너진다.

화면 상단에 유지 중인 값을 표시하고, 바꿔야 할 때를 위해
`[✏️ 출처 바꾸기]` 버튼 하나만 둔다.

### 11-2. 노션 데스크톱 앱의 반영 지연

봇이 저장한 직후, 이미 열려 있던 노션 화면에 기록이 잠깐 나타났다가
사라지는 경우가 있다. **데이터는 정상 저장되어 있다.**

원인은 노션 앱이 외부(API)에서 들어온 변경을 열린 뷰에 즉시 반영하지
못하는 것이다. 그룹화가 걸린 보드 뷰에서 특히 두드러진다.

대응: 확인할 때 `Cmd + R`로 새로고침한다. 봇이 주는
`[🔗 노션에서 보기]` 링크로 연 페이지 자체는 항상 최신이다.
코드로 해결할 수 있는 문제가 아니므로 README 트러블슈팅에 기재한다.

## 12. 개념태그 화면 규격 (v1.5)

### 12-1. 화면 구성

`개념태그`는 다중 선택이고 누적되므로, 선택한 것과 고를 것을 분리한다.

```
[4/10] 개념태그  ※ 세법 › 부가가치세-ch06.매입세액과 납부세액
선택: ⭐공통매입세액재계산 · 공통매입세액 · 납부세액재계산
      ↑ 별표가 제목이 됩니다

[#환급세액재계산 (2)]  [#안분계산 (3)]
[#예정신고기간매입 (1)]  [#실지귀속구분불가 (1)]
[◀ 이전]  [1/3]  [다음 ▶]
[🔍 검색]  [➕ 새 태그]
[⭐ 대표 바꾸기]  [✔️ 선택 완료]
[⬅️ 뒤로]  [❌ 처음부터]
```

- **선택한 태그는 버튼이 아니라 본문 텍스트로** 표시한다.
  선택분까지 버튼으로 두면 다중 선택 시 화면이 계속 길어진다.
- 버튼에는 **아직 선택하지 않은 태그만** 남긴다.
- 태그 해제는 `[🗑 태그 빼기]`로 제공한다(v1.6 구현 확정).
  선택한 태그만 버튼으로 제시하고, 고른 것을 해제한다.
- 미선택 태그가 10개를 넘으면 단원 화면의 페이지 넘김 규격을 재사용한다.
- **선택 상태는 페이지를 넘겨도 유지된다.**

### 12-2. 대표 태그

- 기본값은 **처음 선택한 태그**다. 대부분의 경우 추가 조작이 필요 없다.
- `[⭐ 대표 바꾸기]`를 누르면 **이미 선택한 태그들만** 버튼으로 제시하고,
  고른 것이 대표가 된다.
- 대표는 본문에 `⭐` 표시로 드러낸다.
- 대표 태그가 §10-3의 `개념명` 조합에 쓰인다.
- 태그를 하나만 선택했다면 그것이 대표이며, 버튼을 노출하지 않아도 된다.

### 12-3. 검색

- `[🔍 검색]`으로 글자 일부를 입력하면 그 단원의 태그 중 포함하는 것만 남긴다.
- **검색 상태는 `[➕ 새 태그]`를 거쳐 돌아와도 유지된다.**
  기존에는 전체 목록으로 되돌아가 다시 검색해야 했다.
- 검색을 해제하는 버튼을 함께 둔다.
- 검색 결과가 없으면 안내 후 `[➕ 새 태그]`로 유도한다.

## 13. 정리 내용 서식 변환 규격 (v1.6)

사용자는 정리 내용을 별도 대화창에서 아래 규격으로 받아 텔레그램에
그대로 붙여넣는다. 봇은 이를 노션 블록으로 변환해 페이지 본문에 넣는다.

### 13-1. 변환 규칙

| 입력 | 노션 블록 |
| --- | --- |
| `$$`로 시작해 `$$`로 끝나는 구간 | `equation` (한 줄 `$$ ... $$` 형태도 처리) |
| `:::code <언어>` ~ `:::` 구간 | `code`, language는 구분자에 적힌 값 (기본 `text`, `mermaid` 허용) |
| `## `로 시작하는 줄 | `heading_2` |
| `- `로 시작하는 줄 | `bulleted_list_item` (공백 2칸 들여쓰기는 `children`으로 중첩) |
| `1. `로 시작하는 줄 | `numbered_list_item` |
| 그 외 줄 | `paragraph` |
| 빈 줄 | 블록 구분자로만 사용. **빈 `paragraph`를 만들지 않는다** |

### 13-2. 처리하지 않는 것

굵게·기울임·인용·마크다운 표·인라인 수식은 **입력 규격에서 금지**되어 있으므로
파서도 처리하지 않는다. 규칙을 늘리면 오탐이 늘고 판별이 불안정해진다.

백틱(``` ``` ```) 대신 `:::`를 쓰는 이유는, 텔레그램 클라이언트가 전송 시점에
마크다운을 해석해 백틱을 제거하고 `entities`로 넘길 수 있기 때문이다.

### 13-3. 수식 실패 폴백

**내용 유실이 가장 큰 문제다.** 노션이 잘못된 LaTeX를 거부하거나 빈 블록으로
만들면, 그 수식을 `code` 블록으로 대체 저장하고 텔레그램으로 알린다.

    ⚠️ 수식 2번이 렌더되지 않아 코드블록으로 저장했습니다.

수식 하나가 실패했다고 기록 전체의 저장을 중단하지 않는다.

### 13-5. 입력 규격 주의사항 (v1.8)

정리 내용을 다른 대화창에서 받아올 때 **규격에 반드시 포함**한다.

- **수식 안에서만 퍼센트를 `\%`로 쓴다.** 수식(`$$ ... $$`) 안에서
  `%`를 그냥 쓰면 그 줄의 나머지가 조용히 사라진다(§14-2).
  **수식 밖의 평범한 문장·목록에서는 그냥 `%`를 쓴다.**
  파서는 수식 블록 밖의 글자를 손대지 않으므로, 밖에서 `\%`를 쓰면
  노션에 역슬래시가 그대로 보인다.
- **수식 안의 한글은 `\text{}`로 감싼다.**
- **목록 중첩은 두 겹까지만 쓴다**(§14-3).
- 제목은 `## `(공백 포함)을 쓴다. `#` 하나는 텔레그램이 해시태그로
  인식할 수 있다(§14-1).

### 13-4. 왕복 일관성

`/export`(§16)는 노션 블록을 읽어 마크다운으로 되돌린다.
**저장과 내보내기는 같은 대응표를 공유해야 한다.** 저장할 때 `equation`으로
넣은 것은 내보낼 때 `$$ ... $$`로, `code`는 `:::code <언어>`로 복원한다.
두 표가 어긋나면 "저장은 됐는데 내보내면 깨지는" 상태가 된다.

### 14-1. 텔레그램 클라이언트의 서식 흡수 — ✅ 실측 완료 (2026-09-12)

같은 원문을 맥 데스크톱 앱과 iOS 앱에서 각각 전송해 `message.text`와
`message.entities`를 비교했다.

| 기호 | 원본 | 맥 데스크톱 | iOS ("서식 없이 보내기") |
| --- | --- | --- | --- |
| `$$` | 2 | 2 | **0 (소실)** |
| `##` | 2 | 2 | **0 (소실)** |
| `- ` (목록) | 7 | 7 | 3 (목록용 4개 소실, 뺄셈 기호만 잔존) |
| `_` | 6 | 6 | 6 (잔존) |
| `:::` | 2 | 2 | 2 (잔존) |
| `\` (역슬래시) | 7 | 7 | **0 (소실)** |
| `—` (긴 대시) | 0 | 0 | **0 (변환 없음)** |
| `entities` | — | 없음 | 없음 |

> 역슬래시·긴 대시 두 행은 2026-09-12 2차 실측으로 추가되었다.
> 1차 실측에서 이 두 축을 재지 않은 것이 §15-3 사고의 직접적 원인이다.
> **측정하지 않은 축의 문제는 영원히 보이지 않는다.**

**결론 1 — 맥 데스크톱은 원문을 전혀 훼손하지 않는다.**
따라서 파서는 `message.text`만 보면 되며, `entities`를 읽어 복원하는
처리는 **불필요하다.** 구현이 단순해진다.

**결론 2 — iOS는 원문 자체가 훼손된 채 도착하며 복구 불가능하다.**
iOS가 붙여넣은 텍스트를 서식 있는 글로 미리 해석하고, 프리미엄이 없어
"서식 없이 보내기"를 선택하면 인식에 쓰인 기호까지 함께 삭제한다.
`entities`가 비어 있어 사후 복원 경로가 없다.

**결론 3 — 살아남은 기호와 소실된 기호의 차이.**
`_` `:::` 는 텔레그램이 서식으로 인식하지 않아 잔존했고,
`##` `$$` 줄머리 `- ` **그리고 역슬래시(`\`)** 는 인식 대상이라 소실됐다.
역슬래시는 마크다운의 이스케이프 문자이므로 함께 제거된다.
사전에 우려했던 밑줄(`_`) 훼손은 발생하지 않았다.

**결론 5 — 윈도우 데스크톱도 안전하다. (2026-09-13 실측)**

윈도우 텔레그램에서 서식이 포함된 원문을 붙여넣으면 다음 안내가 뜬다.

    Pasted as plain text
    Subscribe to Premium to preserve formatting when pasting

**문구는 iOS와 비슷하지만 동작은 정반대다.** 윈도우는 "서식 없이
붙여넣었다"고 알릴 뿐 **원문 글자를 그대로 유지**하며, 저장 후
수식·코드블록·제목이 모두 정상 렌더되는 것을 확인했다.
iOS는 기호 자체를 삭제하지만, 윈도우는 삭제하지 않는다.

따라서 안전 여부는 **데스크톱이냐 모바일이냐**로 갈린다.

| 환경 | 원문 보존 | 판정 |
| --- | --- | --- |
| 맥 데스크톱 | 완전 | ✅ 안전 |
| 윈도우 데스크톱 | 완전 | ✅ 안전 |
| iOS | 기호 소실 | ❌ 위험 |

**결론 4 — 긴 대시 변환은 일어나지 않는다. (2026-09-12 확정)**
iOS는 하이픈을 긴 대시로 **바꾸지 않고, 목록 마커를 지운다.**
따라서 파서와 감지 어느 쪽에서도 긴 대시를 하이픈과 동일하게
취급하지 않는다. 되살릴 수 없는 것을 되살리는 척하면
§15-2의 목적을 정면으로 거스르게 된다.

**파생 결정 — `#` 하나짜리 제목 표기를 쓰지 않는다.**
텔레그램은 모든 플랫폼에서 `#단어`를 해시태그 엔티티로 자동 인식한다.
`## ` (공백 포함)를 유지하면 이 위험을 피할 수 있다.
노션 순정 마크다운으로 바꿀 실익이 없다.

## 15. 입력 경로와 손상 감지 (v1.7)

### 15-1. 입력 경로

서식이 포함된 정리 내용은 **데스크톱 텔레그램(맥·윈도우)에서 작성한다.**
모바일에서는 서식 기호가 소실되며 복구할 수 없다(§14-1).

README에 다음을 명시한다.

> 수식·코드블록·제목이 포함된 정리 내용은 **컴퓨터 텔레그램**에서 보내십시오.
> 휴대폰에서 보내면 서식 기호가 사라져 내용이 반쪽만 저장될 수 있습니다.
> 서식 없는 짧은 글은 휴대폰에서 보내도 문제없습니다.

### 15-2. 손상 감지 안전망

모바일 오전송을 막을 수 없으므로, **도착한 텍스트에서 훼손 정황을
탐지해 저장 전에 되돌려 보낸다.** 조용히 반쪽 저장되는 것이 최악이다.

| 정황 | 판정 |
| --- | --- |
| `\`로 시작하는 LaTeX 명령어가 있는데 `$$`가 하나도 없음 | 수식 구분자 소실 |
| `:::`가 홀수 개 (여는 것만 있고 닫는 것이 없음) | 코드블록 구분자 소실 |
| `$$`가 홀수 개 | 수식 구분자 일부 소실 |

감지되면 저장하지 않고 안내한다.

    ⚠️ 서식이 깨진 것 같습니다.
    컴퓨터 텔레그램에서 다시 보내주세요.
    [🔁 그래도 저장]  [❌ 취소]

- **입력한 내용은 세션에 보존**하고, 사용자가 강행을 택하면 그대로 저장한다.
- 완전 탐지는 불가능하다. 가장 흔한 사고만 막는 것이 목적이다.

### 15-3. 실패 기록 — iOS 미감지 (2026-09-12)

**구현된 감지가 실제 iOS 전송을 잡아내지 못했다.**
"서식 없이 보내기"를 선택하자 경고 화면 없이 곧바로 저장되었고,
서식이 지워졌다는 안내도 없었다. §15-2가 막으려던 "조용히 반쪽 저장"이
그대로 재현된 것이다.

**원인 (2026-09-12 규명 완료)**

규칙 3개 중 iOS를 잡을 수 있는 것은 ①번뿐이었다.

| 규칙 | iOS 도착 상태 | 판정 |
| --- | --- | --- |
| ② `:::`가 홀수 | 2개 (잔존, 짝수) | 통과 |
| ③ `$$`가 홀수 | 0개 (전부 소실, 0은 짝수) | 통과 |
| ① LaTeX 명령어가 있는데 `$$`가 0개 | **유일한 방어선** | 여기가 샜다 |

②③은 "짝이 맞는가"를 보는 규칙이라 **구조적으로 iOS를 잡을 수 없다.**
iOS는 기호를 한쪽만 지우는 것이 아니라 전부 지우므로 0개가 되고,
0은 언제나 짝수다.

①번은 `역슬래시 + 영문자 2자 이상`을 찾고 있었다. 역슬래시가 함께
지워지면 `\frac`은 `frac`이라는 평범한 영어 단어가 되어 아무것도
걸리지 않는다. 2차 실측(§14-1)에서 역슬래시 맥 7개 / iOS 0개로 확인됐다.

**수정 — 규칙을 늘리지 않고 ①번의 인식 범위만 넓혔다.**
`\%` `\_` 같은 비영문 명령어와, 역슬래시가 지워져도 남는
`frac{` `text{` 형태의 중괄호를 단서에 포함했다.
코드블록(`:::` ~ `:::`) 내부는 LaTeX 검사에서 제외해
윈도우 경로(`C:\Users\...`) 오탐을 막았다.

**✅ 실측 입증 (2026-09-12):** 맥 정상 원문은 "걸리지 않음",
iOS 전송분은 "수식 명령어가 있는데 `$$` 구분자가 하나도 없습니다"로
정확히 판정되었다. 오탐 없음. **이 항목은 종결한다.**

## 16. `/export` 마크다운 내보내기 (v1.7)

### 16-1. 목적

시험 직전에 원하는 범위의 기록을 **한 파일로 모아 읽기 위한 기능**이다.
노션 자체 내보내기는 페이지마다 파일이 따로 생겨 이 목적에 맞지 않는다.

### 16-2. 흐름

```
/export → 과목 선택 → 범위 선택(전체 / 단원 / 개념태그)
       → 해당 기록의 본문을 읽어 하나의 마크다운으로 합침
       → 텔레그램으로 .md 파일 전송
```

- 대상이 0건이면 안내하고 종료한다.
- 대상이 많으면 진행 상황을 알린다(예: `12건 중 5건 수집 중...`).
- 노션 조회가 연속되므로 초당 약 3회 제한과 429 재시도를 지킨다.

### 16-3. 파일 구성

기록마다 다음 순서로 쓰고, 기록 사이에 `---`를 넣는다.

```
## <개념명>
- 과목 / 단원 / 개념태그 / 지식유형 / 오답유형
- 교재구분 · 문제위치 / 참고출처 / 기록일

<본문을 마크다운으로 복원>
```

정렬은 `단원` → `개념태그` → `기록일` 순으로 한다.

### 16-4. 왕복 일관성 (§13-4)

본문 복원은 저장 파서의 **역방향**이며 같은 대응표를 공유한다.

| 노션 블록 | 마크다운 |
| --- | --- |
| `equation` | `$$` ~ `$$` |
| `code` | `:::code <언어>` ~ `:::` |
| `heading_2` | `## ` |
| `bulleted_list_item` | `- ` (중첩은 공백 2칸) |
| `numbered_list_item` | `1. ` |
| `paragraph` | 그대로 |

내보낸 파일을 다시 붙여넣으면 같은 구조로 저장되어야 한다.

단, 복원은 **표준형**으로 이루어진다. 블록 구조는 같지만 글자는 달라질 수 있다.

- `$$ x $$` 한 줄 형태 → 세 줄 형태로
- `3. 5. 7.` → `1. 2. 3.`으로 재번호
- 문단 사이에 빈 줄이 삽입됨 (§13-1이 빈 paragraph를 만들지 않으므로)

### 16-5. 노션 페이지로 직접 저장 (v1.8)

수집 완료 후 두 가지 선택지를 제시한다.

```
✅ 12건을 모았습니다.
[📥 파일로 받기]   [📄 노션에 저장]
```

**`[📄 노션에 저장]`을 기본 경로로 안내한다.** 통합 정리본은 수십 건을
합친 것이라 텔레그램 메시지 한도(4096자)를 거의 확실히 넘으므로,
파일을 받아 복사·붙여넣기 하는 경로는 실용성이 낮다.

저장 위치는 §17의 추출본 데이터베이스다.

### 16-6. 안내 문구

기존 문구 `"파일을 그대로 다시 붙여넣으면 같은 구조로 저장됩니다"`는
**파일 자체를 봇에 전송하거나 텍스트를 곧바로 보내는 오해**를 낳았다.
실제로 그렇게 하면 `"먼저 /new 로 기록을 시작해주세요"`가 떠서
안내가 안내대로 동작하지 않았다.

`[📄 노션에 저장]`이 생기면 복붙 경로를 안내할 이유가 없어진다.
파일로 받는 경우에도 오해가 없도록 쓴다.

    📥 마크다운 파일로 받았습니다.
    읽기용 파일이며, 봇에 다시 보내도 저장되지 않습니다.
    노션에 모아 두려면 [📄 노션에 저장]을 이용하십시오.

## 17. 추출본 데이터베이스 (v1.8)

### 17-1. 왜 별도 표인가

`/export` 결과를 상위 페이지 밑에 개별 페이지로 흩뿌리면 누적될수록
찾기 어려워진다. **표 하나에 모으면 과목·날짜로 필터하고 정렬할 수 있다.**

학습 기록 표(§1)와 **절대 섞지 않는다.** 통합 정리본이 기록 표에 들어가면
개념태그 누적 횟수가 부풀고, 보드 뷰 그룹마다 거대한 중복 페이지가 끼어든다.

### 17-2. 속성 (5개, 최소 구성)

| # | 속성명 | 타입 | 설명 |
| --- | --- | --- | --- |
| 1 | `제목` | 제목 | `과목 › 범위 · YYYY-MM-DD` 형식으로 봇이 조합 |
| 2 | `과목` | 선택 | 내보낸 범위의 과목 |
| 3 | `범위` | 텍스트 | 전체 / 단원명 / 개념태그명 |
| 4 | `포함건수` | 숫자 | 합친 기록 수 |
| 5 | `생성일` | 생성 일시 | 노션 자동 |

본문에는 §16-3의 파일 구성과 동일한 내용이 들어간다.
블록 수 제한을 넘으면 기존 이어붙이기 로직을 그대로 쓴다.

### 17-3. 생성 시점 (✅ 2026-09-12 실동작 확인)

`/export` → `[📄 노션에 저장]` 실행으로 표가 자동 생성되고
`.env`에 ID가 기록되는 전 과정이 실제로 확인되었다.
`check_notion.py`가 그 표의 속성 5개가 §17-2와 일치함을 확인했다.


**사용자가 아무것도 하지 않아도 되게 한다.**

```
/export에서 [📄 노션에 저장] 선택
  → .env의 NOTION_EXPORT_DB_ID 확인
  → 있으면 그 표에 저장
  → 없으면 학습 기록 표의 부모 페이지 아래에 표를 새로 만들고
     그 ID를 .env에 기록한 뒤 저장
```

setup_notion.py도 이 표를 함께 만들도록 한다(배포용).
check_notion.py는 이 표를 **선택적으로만** 검사한다 —
`/export`를 한 번도 쓰지 않은 사용자에게는 표가 없는 것이 정상이므로,
없다고 오류를 내지 않는다.

### 17-4. 뷰

기본 테이블 하나면 충분하다. 정렬은 `생성일` 내림차순.
사용자가 필요에 따라 과목별 그룹화를 추가할 수 있다.

## 18. 윈도우 환경 메모 (v2.0)

2026-09-13 윈도우 PC에서 실측한 내용이다. README 트러블슈팅의 근거 자료다.

### 18-1. 이모지가 `?` 네모로 표시됨

윈도우 기본 콘솔은 `cp949`를 쓰는 경우가 있어 이모지를 표시하지 못한다.

- **봇은 죽지 않는다.** `errors="replace"` 고정 덕분에 글자만 `?`로 바뀐다.
  이 조치가 없었다면 `UnicodeEncodeError`로 기동 중 중단되었을 것이다.
- **한글은 정상이다.** 단원 102개 읽기, 노션 연결 모두 성공했다.
- 다만 배포판의 첫 화면이 `? 봇을 시작합니다`가 되는 것은 인상이 나쁘다.

**결정: 터미널에 출력하는 줄에서는 이모지를 쓰지 않는다.**
`[봇]` `[완료]` `[오류]` 같은 대괄호 표기로 대체한다.
**텔레그램 메시지의 이모지는 그대로 둔다** — 텔레그램은 어느 환경에서든
정상 표시되며, 버튼 가독성에 기여한다.

### 18-2. PowerShell 실행 정책 오류

가상환경 활성화 시 발생한다. 실제 오류 원문:

    .venv\Scripts\Activate.ps1 : 이 시스템에서 스크립트를 실행할 수 없으므로
    ... Activate.ps1 파일을 로드할 수 없습니다.
    + CategoryInfo : 보안 오류

해결:

    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

실행하면 확인을 묻는다. **`Y`를 입력하고 엔터**를 누른 뒤 다시 활성화한다.
`-Scope Process`이므로 그 창에서만 적용되고 시스템 설정을 바꾸지 않는다.

### 18-3. 경로에 한글·공백이 있으면 어려워진다

`카카오톡 받은 파일\cpa-knowledge-os 복사본\` 같은 경로는
`cd` 명령에서 큰따옴표로 감싸야 하고, 드래그로 넣어도 실패하기 쉽다.

**README 권고: 폴더를 `C:\` 바로 아래처럼 짧고 영문인 경로에 둔다.**
`cd` 입력 후 폴더를 터미널로 드래그하는 방법도 함께 안내한다.

### 18-4. 맥에서 만든 zip이 윈도우에서 안 열릴 수 있다

윈도우 기본 압축 해제가 "압축 폴더가 올바르지 않습니다"로 실패했고,
7-Zip 등 별도 도구로는 해제되었다. 해제 후 한글 폴더명이 자모 분리로 깨졌다.

**배포에는 영향이 적다.** README는 `git clone`과 GitHub의
`Download ZIP`을 안내하며, GitHub이 만드는 zip은 윈도우에서 정상 해제되고
폴더명도 전부 영문이다. 이 항목은 맥에서 직접 압축해 전달한 경로 특유의
문제이므로 참고로만 남긴다.

### 18-5. `Ctrl+C` 종료 지연

윈도우에서 `Ctrl+C`를 눌러도 즉시 종료되지 않고, 여러 번 누르거나
잠시 기다려야 하는 지연이 있다. **맥에서는 발생하지 않는다.**

플랫폼 차이로 보이며 코드 결함이 아닐 가능성이 높다.
무리하게 고치려 들면 종료 처리에 새 결함을 만들 수 있으므로,
**조사 후 안전한 개선이 없다면 README 안내로 처리한다.**

> 종료할 때 `Ctrl+C`를 눌러도 바로 꺼지지 않을 수 있습니다.
> 몇 초 기다리거나 한 번 더 눌러 주세요. 정상입니다.
